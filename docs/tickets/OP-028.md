# OP-028 — Background child lifecycle, retained runs, and fleet inspection

**Status:** Proposed · **Priority:** P1 · **Effort:** L · **Origin:** pi-subagents 0.83.0
**Dependencies:** OP-001, OP-018, OP-022; implements OP-009 with OP-026. Usage feeds OP-017/OP-033.

## Problem and outcome
Outpost needs a durable user-visible representation of active and retained child sessions. Launching a background job is not completion, and closing a client must not lose ownership or results.

## Scope
Persist parent/task/run/child lineage, requested and resolved models, context mode, workspace lease, budget, current activity, result references, and terminal disposition. Support start, acknowledged steer/follow-up, interrupt, stop, inspect, and guarded resume. Distinguish queued, accepted, delivered, and missed steering from proof that the child followed guidance. Retained children expose resumability and expiry explicitly.

Build a desktop fleet view with child tree, activity age, current tool, duration, bounded transcript paging, artifacts, budget consumption, and needs-attention states. Use server events and scoped snapshots, not terminal scraping or repeated model status calls. Completion notifications wake the correct parent once through durable outbox delivery; child completion inside a workflow should not also trigger duplicate independent parent continuations.

Map upstream mission concepts to existing Outpost tasks and run records. Scheduled workflows use OP-004's scheduler; do not install a competing mission store or scheduler. Define server-restart reconciliation separately from client disconnect and in-process runtime replacement.

## Safety and recovery
The extension documents temporary completion replay and artifacts, not a substitute for Outpost's permanent ledger. Preserve required final evidence before retention cleanup. Do not infer process-terminal proof, safe workspace cleanup, or successful execution merely from a timestamp, missing PID, or result file. Unknown process ownership blocks destructive cleanup. Resume revalidates scope, budget, model, and workspace revision; automatic resume needs a reviewed policy.

## Acceptance criteria
- Closing/reopening the desktop retains active children and delivers each outcome once.
- Restart at admission, completion, notification, or resume boundaries cannot duplicate effects.
- Stop and steer target the exact authorized child/subtree; stale or foreign IDs fail.
- Missing usage/artifacts display unavailable or partial accounting, never zero cost or success.
- Transcript inspection remains bounded and identity-scoped.
