# OP-016 — Reviewed procedure learning

**Status:** Proposed · **Priority:** P3 · **Effort:** L · **Origin:** F16 + Hermes /learn
**Dependencies:** OP-007, OP-022; OP-010 for executable procedures, OP-006 for provenance.

## Problem and outcome
Repeated successful work can become reusable knowledge, but automatic self-modification would undermine reproducibility and authority. Users should be able to promote an evidenced procedure into a reviewed skill.

## Scope
Offer “save as procedure” after verified work or from explicitly supplied references. Produce a draft with purpose, prerequisites, steps, failure cases, source citations, and evaluation examples. For large reference collections, use a compact index plus on-demand topic files. Show a version diff against an existing skill and require review before activation. Store evaluation outcomes and allow rollback to an earlier version.

## Safety and recovery
Drafting never changes active instructions or grants capabilities. Exclude credentials, personal data, transient paths, and unsafe shortcuts from generated procedures. Preserve source licensing/provenance and avoid reproducing copyrighted books verbatim. A previously successful execution is evidence to inspect, not proof the procedure is universally safe.

## Acceptance criteria
- A successful task produces a draft without changing any active run.
- Activation records reviewer, source artifacts, version hash, and evaluation results.
- Rejected drafts remain inactive; rollback restores a known version.
- Secret/path sanitization and untrusted-source injection tests cover generated content.
