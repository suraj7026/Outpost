# OP-033 — Ollama quota dashboard and honest parent/child cost accounting

**Status:** Proposed · **Priority:** P1 · **Effort:** M–L · **Origin:** pi-ollama-cloud 0.13.1 + pi-subagents 0.83.0
**Dependencies:** OP-017; OP-028 supplies child receipts. Account-level quota display can ship independently of child execution.

## Problem and outcome
Operators need to know whether background fan-out will exhaust provider quota. Per-token estimates, Cloud account balance, request totals, and task-attributed usage are different measurements and must not be collapsed into a misleading single dollar figure.

## Scope
Add server-side balance/quota and request-histogram retrieval with explicit credential/account ownership, last-updated time, renewal period, and purchased credits when returned. Display stale/unavailable states and allow manual refresh within limits. Coalesce refreshes across clients; use a conservative background cadence, respecting the usage endpoint's documented rate limit. Suppress stale responses after account/provider switches.

Aggregate parent, child, workflow, retry, and watchdog token usage by stable attempt identity. Show measured tokens separately from comparable cost estimates and account-level subscription/credit data. Carry completeness indicators for missing receipts and unknown usage; historical totals must not silently shrink when temporary artifacts expire. Integrate warning thresholds and admission budgets without claiming account balance gives exact per-task spend.

## Safety and recovery
The extension uses published per-token equivalents, not actual subscription charges; unmapped prices return zero and cache-token usage is unavailable. Outpost should show unknown price rather than “free,” and must not invent cache savings. Do not double-count child usage already rolled into a parent result. Quota exhaustion does not authorize changing provider, purchasing credits, or increasing the owner's budget. Its footer is TUI-only; Outpost needs server/API projections, not a copied terminal widget.

## Acceptance criteria
- Parallel client refreshes are deduplicated and transient errors cannot present stale quota as current.
- Account/model switch races cannot display another account's data.
- Each completed attempt is counted once across notification replay and restart.
- Missing receipts/prices produce partial/unknown labels, not zero usage or fabricated charges.
- Warning and admission thresholds are tested without triggering purchases or automatic provider substitution.

## Multi-environment and hub extension
[OP-040](OP-040.md) adds optional external hub/account sources from the newer T3 review. Deduplicate the same account reported through several hosts or hubs, preserve missing/stale quota windows, and separate account capacity from task-attributed tokens. T3's [usage guide](../../../t3code/docs/user/usage.md) explicitly separates hub monitoring from configuring model requests through that hub. Do not present pooled quota as proof that inference or host workload balancing is enabled.
