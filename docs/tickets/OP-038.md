# OP-038 — Explicit peer links and remote subagent delegation

**Status:** Proposed · **Priority:** P2 · **Effort:** XL · **Origin:** T3 linked-environments rescan `2c119bd9`
**Dependencies:** OP-026–OP-029, OP-034, OP-022; remote coding isolation requires an explicitly supported destination workspace contract.

## Problem and outcome
Local subagents and fixed host commands do not establish trusted delegation between independent Outpost environments. A remote child should have durable lineage, a destination grant, and honest result/cancellation recovery without sharing coordinator databases.

## Scope
Create owner-approved peer links bound to destination identity, expiry, capabilities, project scope, and a least-privileged credential. Resolve the destination project explicitly or by a unique verified repository mapping. Validate model/tool/workspace readiness at the destination. Carry an immutable origin and narrowed authority envelope through children/forks. Namespace idempotency keys by caller and persist source-task/destination-run correlation before following results.

Implement bounded remote waits, restartable result followers, correlated supervisor questions, and cancellation acknowledgements. Show “running elsewhere,” disconnected/unknown, revoked, and terminal states in the fleet. Keep Forget local record distinct from Revoke remote grant. Remote work has its own admission receipt; a connected route is not proof a child was admitted.

## Safety and recovery
Destination grants intersect caller authority; a full-access peer must not silently turn a read-only parent into a writer. T3's peer link is routing, not OS confinement, and its restricted-origin rule does not fence all reads. Outpost must enforce both read and write scope and every exact action. The inspected T3 remote delegate path rejects worktree isolation; Outpost must reject unsupported isolation rather than silently run in a shared checkout. Lost cancellation or launch acknowledgement remains uncertain until reconciled.

## Acceptance criteria
- Wrong-host routes, expired/revoked links, and authority escalation fail before remote execution.
- Duplicate launches and restart followers settle one child result without duplicate parent continuation.
- Cross-link project/thread access is denied according to explicit read/write scope.
- Missing/ambiguous repository mappings and unsupported worktree requests fail visibly.
- Independent environments never share a writable ledger as a shortcut.
