# OP-040 — Optional provider hubs, pooled quota, and approved endpoint routing

**Status:** Proposed · **Priority:** P2 · **Effort:** L · **Origin:** T3 usage/hub rescan `2c119bd9`
**Dependencies:** OP-003, OP-017, OP-031, OP-033; separate from OP-037 host placement.

## Problem and outcome
Multiple hosts/accounts can report the same provider quota, and an external inference proxy may already own a pool. Outpost should expose truthful capacity and explicit endpoint policy without assuming usage monitoring configures request routing.

## Scope
Add optional provider-hub records with owner, endpoint, credential reference, supported read-only usage operations, refresh policy, and provenance. Deduplicate the same account reported across environments/hubs, preserving separate windows, reset times, stale/unknown state, and weekly constraints. Serialize/coalesce refreshes so removed hubs or old credentials cannot be resurrected by a late response.

Keep inference configuration separate. If an owner opts into a compatible proxy/endpoint pool, record approved models/accounts/data boundaries, capacity/concurrency, health, attempt identity, and the resolved route when observable. Pin active sessions unless the provider supports an explicit safe handoff. Display opaque proxy routing honestly when the selected underlying account cannot be known. Begin with usage visibility and explicit endpoint selection; automatic inference balancing needs separate adapter qualification.

## Safety and recovery
T3's CLIProxyAPI integration supplies usage information; it is not evidence that T3 itself round-robins all inference calls. Do not import subscription rotation as a way to evade access restrictions, bans, or provider terms. Keep management keys server-side with least privilege and prevent arbitrary outbound/redirect targets. Reset-credit redemption, purchases, and account changes are separate exact-approved mutations, excluded from the initial read-only slice. A quota failure never authorizes silent provider/data-boundary changes or replay of uncertain tool effects.

## Acceptance criteria
- Shared account reports count once without inventing missing quota or billing values.
- Stale/failed refreshes show partial results and cannot restore a removed source.
- Adding a usage hub does not alter any model endpoint or send inference traffic to it.
- Approved endpoint policy rejects unauthorized providers/accounts and exposes route uncertainty.
- Retry tests distinguish safe model-request retry from unknown external actions.
