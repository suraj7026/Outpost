# OP-013 — Doctor, preflight, and complete recovery inventory

**Status:** Proposed · **Priority:** P0 · **Effort:** L · **Origin:** F13 + Hermes
**Dependencies:** None for read-only diagnostics; repairs use existing policy commands.

## Problem and outcome
Outpost has health probes and encrypted ledger/artifact backup, but those do not cover the whole workspace, Pi sessions, browser state, configuration, and key estate. Operators need an honest recovery report, not a green badge implying complete protection.

## Scope
Add read-only diagnostics for model reachability/configuration, ledger integrity, storage capacity, deployment drift, browser dependencies, capability readiness, stale leases, and backup age/coverage. Classify findings as informational, degraded, blocked, or uncertain. Provide redacted export and concrete repair proposals. Inventory each state class with owner, sensitivity, backup method, restore ordering, and whether it is intentionally excluded.

## Safety and recovery
Doctor must not mutate state automatically. Repairs are explicit exact-action commands with before/after evidence. Restored instances stay in dispatch hold until credentials, leases, schedules, and uncertain effects are reconciled. Never clone live schedules or single-use refresh credentials into a second active operator without a documented ownership transfer.

## Acceptance criteria
- Missing credentials/dependencies are diagnosed before unattended work spends inference tokens.
- Read-only diagnosis leaves records and external systems unchanged.
- A disposable restore rehearsal identifies excluded state and cannot dispatch actions.
- Exported diagnostics contain no secret values or private content by default.

## Remote-operation diagnostics
[OP-034](OP-034.md) supplies per-route stages; [OP-035](OP-035.md) supplies Tailscale status; [OP-036](OP-036.md) supplies optional broker/tunnel allocation health; [OP-039](OP-039.md) supplies service ownership/update/resource-pressure checks. Distinguish a client's dead network, cloud sign-in rejection, tunnel transport failure, local server failure, stale endpoint, and incompatible version. Host-side probes cannot prove phone-side reachability. Follow [T3's troubleshooting structure](../../../t3code/docs/user/t3-connect-troubleshooting.md) without automatically disabling VPNs, changing exit nodes, restarting shared services, or exposing diagnostic secrets.
