# OP-039 — Ownership-safe SSH, background service, and resource protection

**Status:** Proposed · **Priority:** P1 · **Effort:** L · **Origin:** T3 remote-operations rescan `2c119bd9`
**Dependencies:** OP-013, OP-034; OP-001/OP-022 define drain/interruption behavior. Reuses existing deployment ownership.

## Problem and outcome
Outpost relies on private SSH access and deployed services. The client needs explainable tunnel/service health and safe lifecycle actions, while heavy agent work must not make the coordinator and administrative access unreachable.

## Scope
Track whether Outpost created or merely discovered a tunnel/server process. Support reconnecting the transport without restarting unrelated services. Provide explicit install/status/repair/restart/uninstall plans for supported deployment modes; retain user data on service removal. Verify downloaded runtime versions/checksums, stage updates, show affected active tasks, and drain or record interruption before approved restart. Keep login, network exposure, background-service enablement, and process health separate.

Add a Linux resource-protection assessment for coordinator, worker processes, SSH, and optional Tailscale using actual service/cgroup ownership. Propose bounded CPU/memory/OOM changes with before/after values and undo. Document platform-specific unattended availability instead of assuming a logged-out/sleeping Mac behaves like a server. Extend doctor with stage-specific route, tunnel, port, credential, service, and resource-pressure diagnostics.

## Safety and recovery
Stop only processes/services whose exact ownership is proven; no pattern-based kills or arbitrary service rewrites. Do not run the entire operator as root simply to install a service. Unknown update/cleanup state retains evidence and blocks destructive retries. Resource protection is privileged configuration, not an automatic repair; it must not starve unrelated workloads on shared hosts.

## Acceptance criteria
- Disconnect/removal leaves discovered pre-existing servers running.
- A failed staged update leaves the prior runtime/configuration recoverable.
- Restart with active work records interruption and does not replay unknown external effects.
- Resource plans are reviewable, reversible, and scoped to owned service units/cgroups.
- Diagnostics never publish SSH keys, pairing URLs, tunnel tokens, or raw secret-bearing stderr.
