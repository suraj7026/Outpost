# OP-008 — Connector bundles and managed MCP lifecycle

**Status:** Proposed · **Priority:** P2 · **Effort:** XL · **Origin:** F08 + Hermes
**Dependencies:** OP-007, OP-013, OP-017; OP-024 is a later discovery optimization.

## Problem and outcome
Manifest staging, executable hashes, probes, and a tool catalogue exist, but do not constitute an integrated connector lifecycle. Operators need to install, inspect, authorize, disable, and recover a connector without granting ambient server authority.

## Scope
Define versioned bundles containing supported tool schemas, launch/transport configuration, credential references, permissions, health probes, and update metadata. Separate installation from activation. Supervise process start, readiness, crash backoff, schema refresh, and disable/revoke operations. Surface concrete tools and requested resources in the client; begin with one narrowly scoped read-only connector before write-capable integrations.

## Safety and recovery
Map every invocation to the real tool and validated arguments before the common gate computes an action digest. Quarantine schema drift and executable hash changes pending review. Do not pass the entire server environment or root credentials to plugins. A plugin process is not an isolation boundary; document and enforce its execution privileges. Disable must fence pending dispatch, not just hide the UI entry.

## Acceptance criteria
- Install/probe/activate/disable survives restart with explicit lifecycle events.
- Revocation blocks previously queued connector calls.
- Schema/executable changes cannot reuse an old exact-action approval.
- Crash loops are bounded and diagnostics redact secrets.
