# OP-023 — Portable continuation packets and branch provenance

**Status:** Proposed · **Priority:** P1 · **Effort:** M–L · **Origin:** T3 + Hermes context references
**Dependencies:** OP-002, OP-001; workspace-aware continuation integrates with OP-019.

## Problem and outcome
Long-running work needs safe continuation in a new session or selected model without pretending that provider-native state transfers perfectly. Context handoff should be inspectable and bounded.

## Scope
Build a versioned handoff packet with objective, relevant messages, decisions, source artifact IDs, open questions, workspace revision, pending verification, and explicit omissions. Let the user preview included context and destination model. Budget the packet against the destination's context window. Persist source/destination lineage and distinguish continuation, conversation fork, and filesystem branch. Restore original sources through references when available rather than relying entirely on lossy prose.

## Safety and recovery
Never embed reusable approval tokens, credentials, or inherited blanket authority. The destination revalidates scope and unresolved actions. Mark summaries as derived context, not trusted instructions. Fail clearly when references are unavailable or the destination cannot support a required capability. Do not claim hidden reasoning or native provider state was preserved.

## Acceptance criteria
- Packet size stays within the configured destination budget with visible omissions.
- Source references and branch lineage remain auditable after restart.
- A handoff cannot reuse expired approval or expose another identity's artifacts.
- Missing sources/capabilities produce a warning or blocked continuation, not fabricated parity.
