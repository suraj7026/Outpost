# OP-035 — Tailscale private HTTPS setup, status, and safe removal

**Status:** Proposed · **Priority:** P1 · **Effort:** M–L · **Origin:** T3 rescan `2c119bd9`
**Dependencies:** OP-034, OP-013; exposure mutations use existing exact-action approvals.

## Problem and outcome
Outpost's homelab already uses Tailscale for administration, but the client expects a private SSH tunnel or configured HTTPS endpoint. Make tailnet access discoverable and diagnosable without weakening pairing/authentication or overwriting unrelated Serve mappings.

## Scope
Read bounded CLI status, MagicDNS name, confirmed tailnet addresses, HTTPS readiness, and relevant exit-node state. Preview a loopback-to-tailnet HTTPS Serve mapping, detect port/mapping conflicts, obtain approval, and persist ownership. Probe the resulting endpoint while clearly distinguishing host-side reachability from client-side reachability. Provide enable, inspect, repair proposal, and remove-owned-mapping actions. Classify shared-address-space VPNs separately unless Tailscale is confirmed.

Add diagnostics for missing CLI/login, permission denied, HTTPS capability disabled, DNS/TLS failure, service not answering, and exit-node interference with an optional Cloudflare tunnel. Redact raw command stderr and secrets. Do not install Tailscale or modify routing/firewall/exit-node settings as a hidden repair.

## Safety and recovery
Private Serve is not public Funnel; public exposure is excluded. Tailnet membership never replaces device enrollment, signatures, revocation, or exact-action approval. Never disable an existing mapping that Outpost does not own. Preserve current HTTPS-or-loopback transport validation. If the mapping succeeds but recording fails, reconcile actual mapping state instead of repeating or deleting blindly.

## Acceptance criteria
- Setup and removal affect only an explicitly approved, owned port/origin mapping.
- Wrong-host HTTPS endpoints cannot become trusted routes through discovery alone.
- Missing/slow/failing CLI calls terminate within bounded limits with sanitized diagnostics.
- Restart retains mapping ownership; a conflicting external change blocks automatic cleanup.
