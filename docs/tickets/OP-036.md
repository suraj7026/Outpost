# OP-036 — Optional Connect-style managed access broker

**Status:** Proposed · **Priority:** P2 · **Effort:** XL · **Origin:** T3 Connect rescan `2c119bd9`
**Dependencies:** OP-034, OP-013, OP-039; OP-004 owns any optional held-webhook execution.

## Problem and outcome
Users outside the tailnet may want remote access without router forwarding. A managed broker can simplify reachability, but it introduces cloud identity, signing authority, tunnel lifecycle, operating cost, and data-handling obligations.

## Scope
Define account-to-environment linking, desired exposure, managed endpoint allocation, connector state, one-time proof-bound bootstrap, environment-issued sessions, and explicit unlink/logout. Preserve Outpost's signed-device/action authority after cloud login. Validate the loopback target; prevent arbitrary broker egress and redirects on identity/bootstrap checks. Journal provisioning checkpoints and generation-fence cleanup against concurrent relink/restart. Keep a stable hostname through supported connector recovery.

Pin and verify managed connector binaries, stage replacement, wait for readiness, and retain the working connector if upgrade fails. Offer redacted diagnostics separating account/link, DNS/TLS, connector, and local service health. Establish cost caps, idle-resource cleanup eligibility, and manual recovery when ownership is uncertain. Do not require Clerk or Cloudflare specifically without an Outpost deployment decision.

## Safety and recovery
Explicitly document the broker's mint-signing trust and tunnel-provider visibility; DPoP is not protection against every compromised-broker action. Revocation commits before external teardown, with retryable cleanup records. Normal session traffic should not pass through an unnecessary application broker proxy. Offline webhook storage is opt-in: bodies and token-bearing paths are sensitive, retained for bounded periods, and destination signatures/delivery deduplication remain mandatory.

## Acceptance criteria
- Stolen bootstrap material without the client key cannot establish a session.
- Wrong environment, replayed nonce, redirected endpoint, and stale allocation generation are rejected.
- Unlink blocks new access even when tunnel cleanup fails.
- Connector upgrade/reclaim/restart preserves identity without claiming continuous availability when the host is asleep.
- Duplicate held webhook delivery admits one occurrence and never bypasses destination verification.
