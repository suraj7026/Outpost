# OP-032 — Ollama web search, fetch, and scoped research cache

**Status:** Proposed · **Priority:** P1 · **Effort:** M–L · **Origin:** pi-ollama-cloud 0.13.1
**Dependencies:** Existing policy/research/artifact services; OP-017 for usage diagnostics. Can ship without OP-031 model discovery or a general MCP catalogue.

## Problem and outcome
Outpost has research-source primitives but needs directly usable search/fetch tools with citations, pagination, predictable freshness, and privacy-aware caching. These tools may support any approved model; they use Ollama Cloud credentials independently of the selected inference provider.

## Scope
Expose search returning bounded titles, URLs, and snippets; allow expanding cached results without another paid search. Fetch extracted text and links in bounded pages with offset/continuation metadata. Preserve canonical source URL, retrieval time, cached/fresh state, content digest, and artifact ID. Offer explicit refresh, cache inspection, deletion, per-task disable, and an owner-enforced kill switch.

Use configurable success/failure TTLs and byte/entry quotas. The extension's defaults—24-hour success, 15-minute selected fetch failures, 500 entries per kind, 256 KiB entries, 8 MiB total—are useful reference values, not final Outpost defaults. Keep auth, throttling, transport, and server errors out of the negative cache. Deduplicate concurrent requests under server ownership rather than inheriting its last-writer-wins multi-process cache.

## Safety and recovery
Queries and URLs leave the server for Ollama Cloud even when inference is local; disclose and authorize that egress. Reject secret-bearing URLs, private/local targets where disallowed, unsupported schemes, and embedded credentials. Treat page content as untrusted data. Cache by authorized identity/account/scope, with deletion propagation and explicit sensitive-content policy; do not reuse the extension's user-global raw-URL cache unchanged. Apply Outpost policy before outbound requests and cache reads. Bound `full` expansion as well as ordinary pages.

## Acceptance criteria
- Cached search expansion makes no extra provider request and identifies its source snapshot.
- Paging is deterministic; large pages/results cannot overflow context or storage limits.
- Fresh/expired/negative-cache/force-refresh behavior is tested, including quota errors.
- Cross-identity cache access and secret-URL leakage are rejected.
- Cancellation and kill-switch changes fence new outbound requests.
