# OP-002 — Context budgets and recoverable compaction

**Status:** Proposed · **Priority:** P0 · **Effort:** L · **Origin:** F02 + T3/Hermes
**Dependencies:** OP-001 for turn ownership; coordinate telemetry with OP-017.

## Problem and outcome
Automatic compaction is disabled in Outpost's Pi adapter. Long tasks need a bounded context policy that preserves evidence and pending decisions without presenting a summary as authoritative state.

## Scope
Expose model context capacity, measured usage versus estimates, reserved output capacity, and a bounded recent-history window. Use Pi's supported compaction lifecycle rather than implementing a parallel agent engine. Persist a compaction checkpoint containing source message ranges, summary version, retained artifact references, unresolved actions, and workspace revision. Keep the normal skills/memory prefix stable during a run; apply ordinary edits next run, while revocation and safety changes take effect immediately. Bound reactive overflow retries and detect no-progress compression loops.

## Safety and recovery
Approval and task authority stay in the ledger, never solely in a summary. Retrieved instructions remain untrusted. On compaction failure, retain the original transcript and offer explicit continuation instead of destructive truncation. Invalidate usage anchors after model switches or context rewrites.

## Acceptance criteria
- Oversized sessions compact or stop with an actionable state; retry loops are bounded.
- Interrupted compaction can recover without losing the original transcript.
- Unknown token counts are visibly estimates; stale model usage is not reused.
- Pending approvals and evidence references survive compression without broadening authority.
