# OP-006 — Curated startup memory and cited hybrid recall

**Status:** Proposed · **Priority:** P1 · **Effort:** L · **Origin:** F06 + Hermes
**Dependencies:** OP-002; integrate approved retrieval through OP-007/OP-008 as appropriate.

## Problem and outcome
Outpost already has scoped FTS5, provenance, and forgetting tombstones, but those primitives are not a complete runtime memory experience. Users should see what is remembered, why it was retrieved, and whether a correction actually persisted.

## Scope
Assemble a small identity/project-scoped startup packet with explicit token limits and immutable per-run version. Add on-demand lexical retrieval first, then evaluate hybrid semantic ranking against a representative corpus. Return cited source records, dates, confidence/provenance, and scope. Keep user preferences separate from task observations. Offer add/correct/forget controls with durable receipts; live tool results show new state even when the session-start prefix remains unchanged.

## Safety and recovery
Use the action gate for writes and prevent cross-identity/project leakage. Never treat retrieved text as policy. Forgotten entries must disappear from embeddings, lexical indexes, caches, and future startup packets; document backup-retention limitations. A model saying “remembered” is not proof of a successful write. Index rebuilds must preserve tombstones.

## Acceptance criteria
- Scoped retrieval rejects unauthorized records before ranking/output.
- Correction/forget operations survive restart and index rebuild.
- Startup memory stays within budget and reports its version.
- A fixed evaluation set measures recall quality and citation accuracy before semantic search is enabled by default.
