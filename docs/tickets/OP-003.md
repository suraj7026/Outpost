# OP-003 — Model health, bounded retry, and approved fallback

**Status:** Proposed · **Priority:** P1 · **Effort:** L · **Origin:** F03 + Hermes preflight
**Dependencies:** OP-001, OP-002; integrate with OP-013 and OP-017.

## Problem and outcome
Outpost selects models explicitly and disables runtime retry. Transient failures should be recoverable without silently changing provider, privacy boundary, cost, or authority.

## Scope
Classify authentication/configuration failures, throttling, transport failures, context overflow, and provider unavailability. Add bounded backoff with jitter and a single retry owner. Record attempt count, elapsed budget, provider identity, error class, and final disposition. User-approved fallback chains must state which provider/model substitutions are allowed and whether data leaves the original endpoint. Scheduled tasks preflight the resolved configuration before inference.

## Safety and recovery
Do not treat a model refusal as a reason to escalate automatically. Never replay uncertain tool effects as part of an inference retry. Resume only from a known safe conversation boundary. Configuration errors should block with one actionable diagnostic rather than spend the retry budget repeatedly. Keep credentials out of diagnostics.

## Acceptance criteria
- Transient failures recover within configured attempt/time budgets; permanent errors fail promptly.
- Disallowed provider changes stop for consent.
- Cancellation prevents subsequent attempts and survives restart.
- Tests demonstrate that tool effects are not duplicated when a response is lost.
