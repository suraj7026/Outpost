# OP-024 — Scoped progressive tool discovery

**Status:** Proposed · **Priority:** P2 · **Effort:** M–L · **Origin:** Hermes
**Dependencies:** OP-008, OP-007, OP-017; defer until catalogue size justifies it.

## Problem and outcome
Large connector schemas can consume context even when irrelevant. Outpost currently has a small `outpost_action` surface, so discovery is an optimization for a future catalogue, not an immediate runtime replacement.

## Scope
Expose a compact capability listing plus search/describe operations that return only the task's granted tools. Fetch full schemas on demand and version them with the catalogue. Search should distinguish no matching capability from an unavailable service. Instrument schema-token savings, discovery latency, and task success before enabling by default. Keep read-only discovery independent from invocation permission.

## Safety and recovery
Unwrap a selected tool into its concrete name and normalized validated arguments before policy checks, approval digesting, logging, and dispatch. Reject/quarantine unsupported or unvalidated executable schemas; Hermes' validator explicitly has fail-open cases that Outpost should not adopt. Do not resolve external schema references by implicit network/file access. Recheck grants after catalogue updates and before invocation.

## Acceptance criteria
- Restricted sessions cannot discover or call tools outside their grants.
- Stale schemas and changed arguments invalidate old approvals.
- Unsupported schemas fail closed with an actionable diagnostic.
- Evaluation shows whether token savings outweigh extra round trips and retrieval failures.
