# OP-012 — Browser profiles, continuity, and human handoff

**Status:** Proposed · **Priority:** P1 · **Effort:** XL · **Origin:** F12
**Dependencies:** OP-001, OP-013, OP-022; authority stays in the existing policy layer.

## Problem and outcome
Outpost has integrated Browser-Use execution and separate Playwright observation/lease primitives. Users need one coherent profile/ownership model and a real handoff when authentication or ambiguous UI state requires a person.

## Scope
Bind persistent browser profiles to explicit identity/project scope. Unify leases, task ownership, current URL, progress evidence, session lifecycle, and takeover state across browser implementations. Support pause-for-human, human-control confirmation, and explicit agent resume. Expose meaningful step evidence and final artifacts without streaming secrets or promising full remote desktop functionality.

## Safety and recovery
Do not let two tasks mutate the same profile concurrently. A handoff suspends autonomous browser effects until ownership returns. Session cookies are credentials: encrypt storage, restrict export, define retention, and include them only in an explicitly scoped recovery plan. After restart or a lost browser process, reconcile page/action state rather than repeating a submit click blindly.

## Acceptance criteria
- Concurrent tasks cannot share a mutable profile lease accidentally.
- Login/captcha handoff pauses the agent and requires explicit resume.
- Restart preserves profile ownership while fencing stale browser workers.
- Unknown form submission does not trigger automatic duplicate submission.

## T3 remote-browser reference
The newer [remote-access guide](../../../t3code/docs/user/remote-access.md) describes environment-owned browser tabs streamed to other devices, explicit take/release control, read-only viewing, and mediated clipboard/file-picker/download interactions. Adapt those behaviors to Outpost's existing browser lease/handoff, rather than a separate remote-desktop subsystem. Transfers and input need their own scoped actions; reconnect must not steal human control or replay a submission. Streaming/media authorization and retained host downloads require explicit expiry/deletion. Source starting point: [PreviewBrowserHost](../../../t3code/apps/server/src/preview/PreviewBrowserHost.ts). This is a source/documentation reference, not a live browser-stream qualification.
