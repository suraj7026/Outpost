# OP-018 — Scoped snapshots, bounded streams, and history paging

**Status:** Proposed · **Priority:** P0 · **Effort:** L · **Origin:** T3
**Dependencies:** None for protocol design; coordinate identifiers with OP-001 and metrics with OP-017.

## Problem and outcome
Outpost currently streams a full public-record snapshot on connection and rotates streams after 60 seconds. Broad desktop state may become costly as history grows; this is an architectural risk, not a measured performance regression.

## Scope
Separate lightweight workspace/task-list summaries from selected-task details and paged history. Define scoped subscription cursors, snapshot watermarks, ordered deltas, tombstones, replay limits, and explicit reset-required messages. Bound replay and live buffers by both item count and bytes. Use one connection/retry owner per environment with jitter, sleep/resume awareness, and cancellation of stale requests. Cache only authorized scopes and discard them on identity changes.

## Safety and recovery
Prevent gaps between snapshot capture and delta subscription. Detect expired cursors and fall back to a scoped snapshot, not silent event loss. Disconnect slow consumers with a documented recovery path rather than buffering indefinitely. Do not filter unauthorized events only in the client.

## Acceptance criteria
- Synthetic large histories keep initial payload and selected-task memory bounded.
- Snapshot/delta race, duplicate event, deletion, gap, and out-of-order fixtures converge correctly.
- Reconnect/sleep/resume never starts multiple retry loops.
- Changing identity clears cached private data and enforces server-side scope checks.

## Multi-route extension
[OP-034](OP-034.md) adds multiple transports to one stable server identity. This ticket continues to own snapshots/cursors, stream replacement, and the single reconnect state machine. Switching from Connect to private HTTPS must not create a second subscription owner, retain stale route permissions, or resend uncertain commands. Use the newer [connection driver](../../../t3code/packages/client-runtime/src/connection/driver.ts) and [route supervisor](../../../t3code/packages/client-runtime/src/connection/supervisor.ts) alongside the original stream-budget references. A route change never changes which machine owns task execution.
