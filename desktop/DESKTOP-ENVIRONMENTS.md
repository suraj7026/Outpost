# Desktop saved environments (A3)

The desktop consumes the native contract in `NATIVE-ENVIRONMENTS.md`. This is a client implementation, not an installation, deployment, replication or handoff feature. Existing deployed v1 servers do not need an upgrade to remain usable.

## Use

- Choose a saved installation using the server-name dropdown attached to the new-task or in-session composer. It shows the saved display name, or the endpoint hostname for the original connection. On pages without a composer, the picker lives in the page header. Selection is navigation, not a mutable transport endpoint. Each installation connects independently; one pending command or outage does not block another.
- The history icon beside the picker opens **All environments · History**, which combines directly received task histories, grouped by owner with connection state and last-sync time. Opening a row selects its owner and task together, even when task IDs coincide. Disconnected history is stale, read-only and memory-only. Closing the app discards this history; it is not an offline backup.
- In **Connection settings → Add environment**, discover a URL, compare the expected installation UUID through a trusted channel and enter a display label. Discovery is explicitly untrusted. **Verify and adopt enrollment** uses the existing Keychain identity without pairing. Only choose **Pair first device** for a genuinely new installation, with its bootstrap token. A failed/ambiguous pairing clears the token and instructs verification/adoption; it is never automatically repeated.
- Saved environments can be renamed, disconnected, removed or given an additional verified route. Choosing any route invokes authenticated registration with the same expected UUID. A matching UUID does not replace HTTPS/SSH trust. Removal deletes only local registry metadata; native pending/corrupt recovery blocks it. It neither stops services nor deletes or revokes remote resources.
- The original v1 connection slot (displayed by its endpoint hostname) retains the original endpoint, first-device pairing and pending retry controls. Unbound pending work must use its original legacy retry path. Exact-route adoption retires the legacy mutation slot natively. Alternate-route adoption requires explicit consent to make the old legacy connection read-only even if the enrolled target is a different installation. The checkbox defaults unchecked and no retirement flag is sent without consent; a rejected adoption does not change legacy behavior. Retired legacy mode remains readable but cannot mutate or manage providers.
- Leaving an environment's Settings page cancels its provider sign-in and Mac callback listener. A late login-start response is cancelled against the original owner. Sign in again on that environment if needed. Switching never sends a callback, credential or command to the newly selected server.

## Source boundaries

- `api.ts`: `environmentApi(environmentId)` closes over an immutable UUID (or explicit `null` legacy slot). Query, command, recovery, provider, artifact and enrollment arguments all use that owner. Upload captures its adapter before reading/hashing the file; begin/chunks/complete cannot move between installations. Local window/browser IPC remains separate.
- `Environments.tsx`: one keyed `Supervisor` per owner. Registry metadata IPC is serialized because the native metadata contract has no revision counter; stale metadata replies must not overwrite a newer registration/selection. This queue does not handle provider requests or command retries.
- `useConnection.ts`: independent records, live overlays, cursor, catalogue, pending information, availability, errors, sync time and operation locks. Lifecycle generations reject old reads/stream callbacks after reconnect, route change, disconnect or removal. Native cancellation precedes successor stream startup. Selection does not cancel the other environment's live connection. When an operation settles after reconnect/disconnect advanced its generation, its history result remains discarded but native connection info is reconciled for that same owner. Lifecycle and request-order guards reject obsolete connection-info replies. Failed reads retain existing recovery blockers; success is never assumed to clear pending storage.
- Both legacy v1 and bound v2 environments use the same native cancellable SSE implementation, including transient live overlays. Legacy `disconnect({})` cancels only the original legacy State; `environment_disconnect({environmentId})` cancels only that registered State. Native request preparation selects the existing signing/protocol contract, without a second transport. Manual disconnect suppresses automatic polling/reconnect for that owner until explicit reconnect.
- Each new connection lifecycle establishes a fresh cursor baseline. An authoritative lower-cursor snapshot from a restored installation replaces prior history, including its recovery-hold records; stale memory remains read-only until that response arrives. Old-generation replies are ignored and same-lifecycle snapshot/event ordering still applies. Reconnect never replays commands.
- `App.tsx` is keyed by owner/route/navigation incarnation. Drafts, model choices, provider prompts, device confirmations and artifact viewers do not leak between owners. Late task-create completion cannot navigate a replacement view. `EnvironmentContext.tsx` requires an owner for artifact operations; image identity includes owner plus artifact identity/hash.
- Wire records remain protocol 1. Kind/id merge keys are used only inside a single owner's supervisor; unified history keys include owner, kind and ID. No provider secret or environment history is written to browser storage. Existing appearance/sidebar preferences are unchanged.

## Validation boundaries

`test-environments.mjs` drives built React components through a synthetic Tauri IPC fixture. It covers identical task/artifact IDs, pending A with successful B, delayed creation/snapshot/artifact responses, upload switching before file hashing, callback and late-login cancellation, independent stream termination, stale read-only history/navigation, device enrollment, verified-route/rename, blocked removal, discovery mismatch, legacy retry/adoption/retirement and ambiguous bootstrap without replay. Controlled pending-state tests also hold a command across reconnect on bound and legacy connections, verify successful completion unlocks controls without retry, retain blockers for unknown outcomes/failed state reads, and reject a delayed reconciliation reply after a newer lifecycle reports corrupt recovery. Restore tests cover a lower authoritative cursor, recovery hold, replacement rather than merging, delayed old-generation replies and same-lifecycle ordering. Legacy live-frame/teardown tests accompany an ongoing-socket native test proving legacy disconnect/reconnect leaves bound B running. It writes synthetic screenshots to `/tmp/outpost-a3-ui`.

Existing desktop regressions now explicitly return the empty native registry when testing legacy compatibility. Stream-specific regressions cover both an explicit bound UUID and legacy mode (`OUTPOST_TEST_LEGACY=1` for `test-stream-ui.mjs`). These fixtures are not real WebView/Keychain or coordinator integration qualification. Native tests remain separate. No live Keychain, provider, SSH or production service is used. The parent installed the pinned Playwright WebKit executable and reran the 58-check environment suite plus provider, image-viewer, appearance, sidebar, execution-evidence, Studio and scroll-containment suites successfully in both Chromium and WebKit. Earlier missing-WebKit reports are historical; real Tauri WebView integration is still a separate qualification.

No durable history cache, peer replication, portable workspace recovery, task move, automatic failover, host installer or iPhone feature is implemented here. Host executor records remain distinct from saved installations. Fresh Astra reviews, parent review and final post-review reruns are complete. Local acceptance is not deployment or live integration qualification: real WebView/Keychain integration, live identity continuity and pending-command recovery still require separate qualification.
