    What scaling would require
    1. A suitable app
      Start with a stateless web service. Move sessions and persistent data out of individual containers.
    2. A Kubernetes deployment
      Supply an image, configuration, health checks, CPU/memory requests and limits. Add a Service for traffic.
    3. A scaling policy
      Use a replica count, or configure a Horizontal Pod Autoscaler. CPU-based HPA needs CPU requests and metrics.
    The metrics server is installed, but no HPA was configured. More replicas still need free capacity. They do not merge the nodes’ RAM or add machines.
    

    Keep these boundaries clear
    • Databases are not ordinary replicas. PostgreSQL and MinIO need their own supported storage, replication and backup design.
    • No automatic live migration. Kubernetes can recreate a managed pod where its constraints permit; it does not move a running process and its memory.
    • Local disks stay local. A volume on one node is not automatically available on the other.
    • The GPU is shared with host software. Existing Ollama runs outside Kubernetes. Avoid competing GPU jobs until that use is coordinated.
    • One control plane, no automatic backups yet. This is centralized management, not a highly available cluster.
